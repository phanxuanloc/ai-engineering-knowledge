Context Window giống mặt bàn có giới hạn. Context Engineering không làm chiếc bàn lớn hơn; nó quyết định tài liệu nào cần đặt lên bàn cho quyết định hiện tại và tài liệu nào nên để ngoài.

Trong hệ thống thực tế, `Context Manager` là application/agent layer thực thi các quyết định đó: retrieve, select, assemble, preserve và refresh context.

## Core Concepts

### Context Engineering vs Prompt Engineering

`Prompt Engineering` chủ yếu hỏi: **Nên chỉ dẫn model thế nào?**

`Context Engineering` rộng hơn: **Model cần biết gì để thực hiện đúng task này?** Prompt là một phần của context, cùng với history, memory, retrieved knowledge, source code, project rules, tool definitions/results và environment/application state.

### Context Sources

Context có thể đến từ nhiều source:

- system/application instructions;
- user request và conversation history;
- long-term memory hoặc structured working state;
- retrieved knowledge/RAG;
- source code, files, repository rules;
- tool definitions và tool results;
- tests, logs, traces, database/configuration state;
- external environment/application state.

Một source **có sẵn** không đồng nghĩa nó nên vào Context Window. Source chỉ tạo khả năng; retrieval và selection quyết định usefulness.

### Retrieve vs Select

<ImportantDistinction title="Retrieve ≠ Select">
  Retrieve tạo candidates. Select quyết định candidate nào đáng chiếm context
  capacity cho current decision.
</ImportantDistinction>

**Retrieve** tìm information có thể hữu ích bằng keyword/lexical search, semantic search, code references, memory lookup, tools, logs hoặc evidence từ step trước.

**Select** đánh giá candidates theo current decision. Signals có thể gồm:

- relevance;
- usefulness cho decision hiện tại;
- priority/authority;
- freshness;
- redundancy;
- token cost;
- confidence/source quality khi phù hợp.

Retrieval score là **một signal**, không phải final selection rule. Một file match query mạnh vẫn có thể kém hữu ích hơn fresh evidence trực tiếp giải thích failure. Runtime trace tiếp theo cho thấy sự khác biệt này khi current decision thay đổi.

### Read the state transitions

**Selection is decision-specific.** `auth route` và `fresh 401 log` phục vụ decision đầu; verifier evidence phục vụ decision thứ hai; focused tests và fresh runtime result phục vụ verification. Một item hữu ích cho task không nhất thiết hữu ích **ngay lúc này**.

**Working State carries continuity.** Agent giữ compact state gồm `goal`, `constraints`, `verifiedFindings`, `decisions`, `changesMade`, `unresolvedQuestions` và `nextActions`. Nó không kéo toàn bộ history sang invocation tiếp theo.

**Working State is not raw evidence.** Summary hoặc hypothesis được carry forward không tự trở thành source of truth. Khi decision cần kiểm chứng, agent phải retrieve evidence có provenance và freshness phù hợp.

**Context is reconstructed, not endlessly appended.** Khi state thay đổi, old search output hoặc test result có thể stale và bị evict. Agent preserve điều cần nhớ, release evidence đã obsolete rồi retrieve cho current decision mới.

Canonical lifecycle đầy đủ nằm tại [Context Engineering Map](./context-engineering-map.mdx). Selected context còn phải đi qua quality, budget, compression và assembly trong [Context Optimization](./context-optimization.mdx); freshness, metrics và trust boundaries được xử lý tại [Context Operations](./context-operations.mdx).

## When to Use

Context Engineering đặc biệt quan trọng khi:

- coding agent cần đọc repository lớn;
- task có nhiều tool calls/model invocations;
- RAG trả nhiều candidates;
- conversation/history dài;
- environment state thay đổi trong quá trình làm;
- model trả lời kém dù prompt wording có vẻ ổn;
- cost/latency/noise tăng vì context ngày càng phình.

Với task đơn giản chỉ cần vài facts ổn định, không cần dựng Context Manager phức tạp.

## Common Mistakes

- **Context Window = Context:** nhầm capacity với information thực tế.
- **More context = better:** thêm noise vì window còn chỗ.
- **Retrieve = Select:** coi top search result là context mặc định.
- **Static context for dynamic task:** không refresh evidence sau khi state thay đổi.
- **Keep everything forever:** history/tool output chỉ append, không có eviction.
- **Treat working state as truth:** summary/hypothesis được carry forward nhưng không còn raw evidence/provenance.

3. Không. Context nên thay đổi theo current decision; preserve important state, retrieve evidence khi cần.
4. Giữ goal, constraints, verified findings, decisions, changes, questions, next actions; không thay thế raw evidence/provenance khi decision cần kiểm chứng.
