# Context Engineering: Foundations & Lifecycle

## TL;DR

<TLDR>

`Context Engineering` là việc quyết định **model cần biết gì cho current decision** và quản lý information đó qua nhiều invocation. `Context Window` chỉ là capacity model có thể xử lý trong một invocation; window lớn hơn không tự chọn đúng context. Mental rule xuyên suốt: **Relevant context > More context**.

</TLDR>

<Remember title="Relevant context > More context">
  Nhiều token hơn không tự động tạo ra quyết định tốt hơn. Đúng information,
  đúng thời điểm và đúng role quan trọng hơn việc đưa mọi thứ vào model.
</Remember>

Mental model đơn giản:

- **Context** = những information model thực sự nhận ở invocation hiện tại.
- **Context Window** = capacity tối đa của invocation đó.
- **Context Engineering** = decision process chọn, tổ chức, duy trì và refresh information nào nên chiếm capacity.
- **Context Manager** = application/agent layer thực thi các quyết định context trong hệ thống thực tế.

## Core Concepts

### Context Engineering vs Prompt Engineering

`Prompt Engineering` chủ yếu hỏi: **Nên chỉ dẫn model thế nào?**

`Context Engineering` rộng hơn: **Model cần biết gì để thực hiện đúng task này?** Prompt là một phần của context, cùng với history, memory, retrieved knowledge, source code, project rules, tool definitions/results và environment/application state.

### Context Sources

Context có thể đến từ nhiều source:

- system/application instructions;
- user request và conversation history;
- long-term memory hoặc structured working state;
- retrieved knowledge/RAG;
- source code, files, repository rules;
- tool definitions và tool results;
- tests, logs, traces, database/configuration state;
- external environment/application state.

Một source **có sẵn** không đồng nghĩa nó nên vào Context Window. Source chỉ tạo khả năng; retrieval và selection quyết định usefulness.

### Retrieve vs Select

<ImportantDistinction title="Retrieve ≠ Select">
  Retrieve tạo candidates. Select quyết định candidate nào đáng chiếm context
  capacity cho current decision.
</ImportantDistinction>

**Retrieve** tìm information có thể hữu ích bằng keyword/lexical search, semantic search, code references, memory lookup, tools, logs hoặc evidence từ step trước.

**Select** đánh giá candidates theo current decision. Signals có thể gồm:

- relevance;
- usefulness cho decision hiện tại;
- priority/authority;
- freshness;
- redundancy;
- token cost;
- confidence/source quality khi phù hợp.

Retrieval score là **một signal**, không phải final selection rule. Một file match query mạnh vẫn có thể kém hữu ích hơn một fresh test result hoặc source fragment trực tiếp giải thích failure.

### Selection is decision-specific

Context không được tối ưu cho “toàn task” một cách tĩnh. Current decision thay đổi khi agent tiến triển.

Ví dụ `Fix login 401`:

1. **401 xảy ra ở đâu?** → route, auth middleware, fresh error.
2. **Token bị reject vì sao?** → verifier, issuer/audience/expiry evidence.
3. **Fix đúng chưa?** → diff, focused tests, fresh runtime result.

Information hữu ích ở bước 1 không nhất thiết còn cần ở bước 3.

### Useful Does Not Mean Simultaneous

Khi toàn bộ useful context lớn hơn một invocation, agent nên chia task thành nhiều decisions:

`Retrieve/Select → Reason/Act → Preserve important state → Release obsolete context → Retrieve for next decision`

<KeyInsight title="Useful does not mean simultaneous">
  Information hữu ích cho toàn task không cần cùng tồn tại trong một Context
  Window. Preserve goal, constraints, verified findings và next actions; refresh
  evidence theo decision tiếp theo.
</KeyInsight>

### Working State Across Invocations

Working state là compact structured memory giúp carry forward task state mà không kéo toàn bộ history.

Một coding-agent working state có thể giữ:

- `goal`;
- `constraints`;
- `verifiedFindings`;
- `decisions`;
- `changesMade`;
- `unresolvedQuestions`;
- `nextActions`.

Working state không thay thế raw evidence. Nó là state summary có provenance/uncertainty phù hợp để quyết định invocation tiếp theo cần retrieve gì.

### Context Lifecycle

Canonical lifecycle của topic được giữ tại [Context Engineering Map](./context-engineering-map.mdx). Foundations tập trung vào đoạn đầu của lifecycle:

**Sources → Retrieve → Candidates → Select → selected context**.

Sau đó selected context đi qua quality/budget/compression/assembly trước model invocation; phần này nằm ở [Context Optimization](./context-optimization.mdx). Quan sát, metrics, freshness và trust boundaries nằm ở [Context Operations](./context-operations.mdx).

### What changed between invocations?

Ở invocation đầu, agent cần xác định 401 xảy ra ở đâu. Khi đã có verified finding, raw route/search output có thể rời Context Window; invocation kế tiếp dùng verifier evidence. Sau code change, old log/test output trở thành stale và phải được thay bằng fresh verification evidence.

Working State nối các invocation bằng `goal`, `constraints`, verified findings, decision/change và next action. Nó không biến summary thành source of truth: khi decision cần kiểm chứng, agent vẫn phải retrieve raw evidence có provenance phù hợp.

User yêu cầu agent sửa lỗi `401` trong một repository lớn.

Bad approach: đưa toàn repo, toàn chat history và hàng nghìn log lines vào một prompt vì “window còn chỗ”.

Better approach:

- pin user goal + critical repository constraints;
- retrieve auth path và fresh failing evidence;
- select vài source fragments trực tiếp cho current decision;
- reason/act;
- save verified finding vào working state;
- evict obsolete search output;
- retrieve fresh evidence cho decision kế tiếp.

Khi task tiến triển, context được **reconstructed**, không chỉ append mãi.

## When to Use

Context Engineering đặc biệt quan trọng khi:

- coding agent cần đọc repository lớn;
- task có nhiều tool calls/model invocations;
- RAG trả nhiều candidates;
- conversation/history dài;
- environment state thay đổi trong quá trình làm;
- model trả lời kém dù prompt wording có vẻ ổn;
- cost/latency/noise tăng vì context ngày càng phình.

Với task đơn giản chỉ cần vài facts ổn định, không cần dựng Context Manager phức tạp.

## Common Mistakes

- **Context Window = Context:** nhầm capacity với information thực tế.
- **More context = better:** thêm noise vì window còn chỗ.
- **Retrieve = Select:** coi top search result là context mặc định.
- **Static context for dynamic task:** không refresh evidence sau khi state thay đổi.
- **Keep everything forever:** history/tool output chỉ append, không có eviction.
- **Treat working state as truth:** summary/hypothesis được carry forward nhưng không còn raw evidence/provenance.
