# Threat Modeling & Attack Surface

## TL;DR

<TLDR>

Threat Modeling là phân tích architecture trước incident để tìm **assets, entry points, trust/privilege boundaries và attack paths** có impact đáng kể. Thay vì đoán mọi kiểu tấn công, hãy ưu tiên đường đi **Untrusted Input → Privileged Capability → Valuable Asset** và đặt controls để phá đường đó hoặc giảm blast radius.

</TLDR>

Threat modeling hỏi: **đường này tồn tại không, weakness nào làm nó khả thi, và control nào có thể cắt nó trước asset?**

## Core Concepts

### Attack Surface

Attack Surface là tổng các điểm mà attacker hoặc untrusted input có thể tương tác với system: public API, uploaded files, webhooks, external content, repository issues, network ports hoặc third-party integrations. Thêm feature/integration thường đồng thời mở rộng attack surface.

### Privilege Boundary

Một component trở nên đặc biệt nhạy cảm khi nó có capability mà nguồn input không có. Public user chỉ được tạo issue nhưng Coding Agent lại có thể push code hoặc chạy terminal: agent trở thành một **privilege bridge** nếu untrusted input có thể điều khiển privileged action.

### Threat, Vulnerability và Risk

- **Threat:** điều xấu có thể xảy ra, ví dụ attacker khiến agent deploy malicious code.
- **Vulnerability:** weakness cho phép threat, ví dụ agent có broad deployment permission và thiếu approval gate.
- **Risk:** hậu quả và likelihood của threat trong context thực tế.

### Break the Attack Path

Threat không cần biến mất hoàn toàn để architecture an toàn hơn. Nếu agent chỉ được create PR, còn CI + human review + branch protection kiểm soát merge/deploy, prompt injection vẫn có thể xảy ra nhưng đường tới production đã bị giới hạn.

<Principle label="Threat vẫn còn, blast radius nhỏ hơn">Security control tốt có thể làm attack path khó hoặc không thể hoàn tất ngay cả khi upstream component bị manipulate.</Principle>

## Example

Support Agent nhận Customer Message, đọc Orders DB và gọi Refund API. Customer Message là entry point. Threat là attacker manipulate agent để refund trái phép. Nếu Refund API tự enforce `amount <= $100`, control nằm ở authorization/policy boundary thay vì phụ thuộc vào reasoning của model; prompt injection thành công vẫn không tạo capability refund `$10,000`.

## When to Use

- Trước khi expose endpoint, integration hoặc privileged automation mới.
- Khi một service/agent nối untrusted input với database, shell, CI/CD hoặc cloud APIs.
- Khi review architecture và cần ưu tiên security work theo attack path có impact lớn.
- Sau incident để tìm boundary/control đã thiếu thay vì chỉ patch symptom.

## Common Mistakes

- **Liệt kê vulnerability không gắn architecture:** threat model phải chỉ ra entry point, path và asset/impact.
- **Threat = vulnerability:** threat là điều có thể xảy ra; vulnerability là weakness cho phép nó.
- **Cố loại bỏ mọi threat:** thực tế thường cần ưu tiên risk và phá các attack path quan trọng nhất.
- **Model/AI quyết định security:** privileged API phải enforce invariant quan trọng độc lập với model output.
