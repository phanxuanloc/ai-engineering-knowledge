# Stack & Queue Fundamentals

## TL;DR

<TLDR>

**Stack = LIFO**: item vào sau được lấy ra trước. **Queue = FIFO**: item vào trước được xử lý trước. Hai data structure này đơn giản nhưng là nền cho Undo/call stack, job processing, DFS và BFS.

</TLDR>

<Principle label="Decision rule">Nếu requirement nói “mới nhất trước”, nghĩ Stack. Nếu requirement nói “đến trước xử lý trước”, nghĩ Queue.</Principle>

## Core Concepts

### Stack

Operations cốt lõi là `push()` để thêm lên top và `pop()` để lấy item trên cùng. Với chuỗi thao tác `A → B → C`, các lần `pop()` trả `C → B → A`.

Undo là ví dụ tự nhiên: nếu Coding Agent vừa create file, modify file rồi delete file, thao tác delete là thay đổi gần nhất nên phải được undo trước.

### Queue

Operations cốt lõi là `enqueue()` để thêm vào cuối hàng và `dequeue()` để lấy item ở đầu. Với các job đến theo thứ tự `A → B → C`, FIFO xử lý `A → B → C`.

Queue data structure trong memory không đồng nghĩa với production message queue như Kafka, SQS hay RabbitMQ. Các hệ thống đó thêm persistence, acknowledgment, retry và distributed consumption, dù vẫn mang queue-like ordering semantics.

### Connection tới graph traversal

Queue và Stack quyết định **node nào được xử lý tiếp theo**:

- `Queue + FIFO` làm các node được discover trước đi trước, tạo mental model của BFS theo từng tầng.
- `Stack + LIFO` ưu tiên node mới discover gần nhất, tạo mental model của DFS đi sâu một nhánh.

## Example

```ts
const undoStack: Operation[] = [];
undoStack.push(createUserFile);
undoStack.push(modifyAppFile);
undoStack.push(deleteOldAuth);

const latestChange = undoStack.pop(); // deleteOldAuth
```

Với job queue, requirement lại ngược lại: job đến trước nên được xử lý trước.

## When to Use

- Dùng Stack cho Undo, backtracking, call-stack-like processing hoặc DFS-style traversal.
- Dùng Queue khi cần FIFO, work scheduling đơn giản hoặc BFS-style traversal.
- Với production jobs dài, dùng durable messaging infrastructure khi cần persistence/retry/distributed workers; đừng nhầm với một Queue trong process memory.

## Common Mistakes

- **Đảo LIFO và FIFO:** Stack lấy item mới nhất; Queue lấy item cũ nhất trong hàng.
- **Nghĩ mọi queue đều strict FIFO:** production messaging có thể thay đổi ordering tùy partitioning, concurrency và product semantics.
- **Chọn Stack/Queue chỉ theo tên use case:** hãy nhìn operation order thật sự mà requirement cần.

3. Vì sao Queue liên hệ tự nhiên với BFS?
4. Message Queue production khác Queue trong memory ở điểm nào?

<details>
<summary>Answers</summary>

1. Stack vì Undo cần LIFO: thay đổi gần nhất được hoàn tác trước.
2. Queue vì cần FIFO.
3. FIFO làm các node được discover sớm hơn được xử lý trước, nên traversal tiến theo từng tầng.
4. Messaging infrastructure còn có persistence, retry, acknowledgment, distributed consumers và các delivery semantics khác.
