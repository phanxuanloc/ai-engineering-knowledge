# Hashing & Hash Table Fundamentals

## TL;DR

<TLDR>

Hash Table dùng **key để tính ra khu vực cần lưu hoặc tìm**, thay vì scan toàn bộ collection. `HashMap` phù hợp với `key → value`, còn `HashSet` phù hợp với membership/uniqueness; lookup thường gần `O(1)` ở average case nhưng collision vẫn có thể làm chậm.

</TLDR>

### Collision

Hai key khác nhau có thể rơi vào cùng bucket. Đây là **hash collision**. Hash Table phải giữ và phân biệt các key thật trong bucket; hash không phải unique ID và collision không đồng nghĩa value mới tự động ghi đè value cũ.

### Vì sao chỉ là `O(1)` average?

Khi hash phân bố key tốt, mỗi lookup chỉ cần đi tới một bucket nhỏ nên thường gần `O(1)`. Nếu rất nhiều key collision vào cùng khu vực, lookup phải kiểm tra nhiều key hơn và có thể degrade đáng kể; về lý thuyết worst case có thể tới `O(n)` tùy implementation.

## Example

Một Coding Agent khám phá repository lớn cần hai cấu trúc khác nhau:

```ts
const visitedFiles = new Set<string>();
const fileCache = new Map<string, string>();

if (!visitedFiles.has(path)) {
  visitedFiles.add(path);
  const content = readFile(path);
  fileCache.set(path, content);
}
```

`visitedFiles` chỉ trả lời “đã xử lý chưa?”, còn `fileCache` giữ mapping `filePath → fileContent`.

## When to Use

- Dùng `HashMap` khi operation chính là exact lookup theo key.
- Dùng `HashSet` khi operation chính là membership, deduplication hoặc uniqueness.
- Dùng List/Array khi ordering và traversal tuần tự mới là requirement chính.
- Không chọn Hash Table chỉ vì thấy `O(1)`; memory overhead, ordering và access pattern vẫn là trade-off thực tế.

## Common Mistakes

- **Nghĩ hash là unique ID:** hai key khác nhau vẫn có thể collision.
- **Nghĩ Hash Table luôn O(1):** `O(1)` là average-case intuition, không phải guarantee tuyệt đối.
- **Dùng HashMap khi chỉ cần membership:** HashSet diễn đạt intent trực tiếp hơn.
- **Dùng HashSet/HashMap khi requirement chính là ordering:** cấu trúc cần chọn theo operation thực sự, không theo Big-O riêng lẻ.

## Self-test

1. Khi nào nên dùng HashSet thay vì HashMap?
2. Collision là gì và vì sao hash không phải unique ID?
3. Vì sao Hash Table thường được mô tả là `O(1) average`?
4. Coding Agent cần `filePath → fileContent`; cấu trúc nào phù hợp?

<details>
<summary>Answers</summary>

1. Khi chỉ cần biết key có tồn tại hoặc cần deduplicate, không cần value đi kèm.
2. Collision xảy ra khi hai key khác nhau rơi vào cùng bucket; implementation vẫn phải phân biệt key thật.
3. Phân bố hash tốt giữ bucket nhỏ, nhưng collision xấu có thể làm lookup phải kiểm tra nhiều item hơn.
4. HashMap vì requirement là mapping từ key sang value.
