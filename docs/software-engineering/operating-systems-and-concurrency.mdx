# Operating Systems & Concurrency

Operating Systems & Concurrency explains **where work executes, what it shares, what it waits for and which finite resource limits throughput or correctness**.

## Topic Overview

After identifying the execution boundary, use four diagnostic lenses: **shared state, waiting, memory and CPU**. They are independent lenses, not a mandatory runtime sequence.

## Recommended Order

Go from execution boundaries → synchronization → waiting model → memory → CPU scheduling. In production debugging, jump directly to the lens matching the observed bottleneck.
