## When to Use
- Debug API/worker latency khi chưa rõ CPU-bound, I/O-bound hay lock-bound.
- Debug race condition, deadlock, OOM hoặc high peak working set.
- Thiết kế bounded concurrency và worker pools cho AI systems.

## Common Mistakes
- **Một concurrency model cho mọi workload:** CPU-bound và I/O-bound cần strategy khác nhau.
- **Race → thêm lock ngay:** phải tìm shared invariant và synchronization boundary trước.
- **OOM = leak:** peak concurrency cũng có thể vượt memory limit.
- **CPU thấp = khỏe:** system có thể đang chờ lock/I/O/downstream.

## Self-test
1. Shared state, waiting, memory và CPU saturation dẫn tới những câu hỏi debugging nào?
2. Vì sao concurrency không đồng nghĩa parallelism?
3. CPU thấp nhưng latency cao thì điều tra gì trước khi scale CPU?

<details><summary>Answers</summary>
1. Atomicity; I/O/locks/downstream; working set/leak/OOM; runnable work/scheduling.
2. Scheduler có thể interleave nhiều tasks trên ít cores; parallelism cần simultaneous compute.
3. I/O wait, lock contention, blocked workers và downstream latency.
</details>
