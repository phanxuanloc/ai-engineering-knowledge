# Networking & Web Fundamentals

## TL;DR

<TLDR>

Một web request đi qua nhiều boundary trước khi chạm business logic. Mental model nền tảng là **Domain → DNS → IP → Routing → Firewall/NAT → TCP:port → TLS → HTTP → Proxy/LB → Application → Cache/Data**; debug đúng layer giúp tránh sửa application khi request còn chưa tới HTTP.

</TLDR>

## Example

Khi gọi partner API:

```text
DNS                        ✓
Route                      ✓
TCP destination:443        timeout
Private IP                 10.10.1.15
Outbound NAT IP            14.1.2.9
Partner allowlist          14.1.2.3 only
```

Đừng sửa `/orders` hoặc JSON trước. Request đang fail ở network/TCP boundary; outbound IP cũng không khớp allowlist.

## When to Use

- Khi API/service call timeout hoặc connection refused.
- Khi cần phân biệt DNS/routing/firewall với TLS/HTTP/application failure.
- Khi browser fail nhưng curl/Postman thành công.
- Khi thiết kế service sau proxy/load balancer.
- Khi backend data đúng nhưng client vẫn thấy dữ liệu stale.

## Common Mistakes

- **Gọi mọi failure là “API lỗi”:** nhiều failure xảy ra trước HTTP/application.
- **Debug sai layer:** có `401` mà vẫn bắt đầu từ DNS/firewall, hoặc TCP timeout mà sửa JSON.
- **Trộn responsibility:** NAT, proxy, TLS, HTTP và CORS giải quyết các boundary khác nhau.
- **Đọc page overview như một bài chi tiết:** overview chỉ là mental map; chi tiết nằm ở bốn bài con canonical phía trên.

## Self-test

1. DNS resolve đúng nhưng `IP:443` timeout: bạn đang ở nhóm bài nào?
2. Nhận `HTTP 401`: nên ưu tiên network hay authentication?
3. Curl thành công nhưng browser báo CORS: failure thuộc network connectivity hay browser policy?
4. Backend data mới nhưng browser vẫn cũ: layer nào nên được nghi vấn?

<details>
<summary>Answers</summary>

1. Network Addressing & Routing / transport connectivity boundary.
2. Authentication/application layer.
3. Browser CORS/Same-Origin Policy.
4. Cache/CDN freshness/invalidation.
