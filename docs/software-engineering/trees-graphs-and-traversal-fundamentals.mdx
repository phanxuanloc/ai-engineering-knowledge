## TL;DR

<TLDR>

## Core Concepts

### Tree và Graph

Tree biểu diễn hierarchy như file-system structure, DOM hoặc AST. Một node non-root thường có một parent và không tạo cycle quay về ancestor.

Graph tổng quát hơn: `Node + Edge`. Dependency graph của repository là ví dụ điển hình vì một module có thể được nhiều module khác dùng và graph có thể xuất hiện cycle.

### BFS — Breadth-First Search

BFS dùng **Queue**. Vì FIFO xử lý node được discover trước, traversal hoàn thành các node gần source trước khi đi sang layer xa hơn. Trong unweighted graph, property này làm BFS phù hợp để tìm path có **ít edge/hop nhất**.

### DFS — Depth-First Search

DFS dùng **Stack** hoặc recursion dựa trên call stack. Mental model là: chọn một branch, đi sâu tới khi không còn neighbor chưa xử lý, sau đó quay lại **chỗ rẽ gần nhất** và thử branch khác.

<Principle label="Không phải hai bước nối tiếp">BFS và DFS là hai traversal strategy khác nhau. Chọn strategy từ requirement; không mặc định chạy BFS để tìm path rồi chạy DFS sau đó.</Principle>

### `visited` giải quyết cycle và duplicate work

Graph có thể dẫn trở lại node cũ. `HashSet visited` trả lời nhanh “node này đã xử lý chưa?”, nhờ đó traversal không chạy lặp vô hạn và không làm lại cùng work.

Mental model ghép lại:

- Queue/Stack quyết định **đi đâu tiếp**.
- HashSet quyết định **đã đi qua đâu rồi**.

## Example

Một Coding Agent cần tìm dependency chain có ít hop nhất từ `App` tới `vulnerable-lib`:

```ts
const queue = [{node: 'App', path: ['App']}];
const visited = new Set<string>();

while (queue.length > 0) {
  const current = queue.shift()!;
  if (visited.has(current.node)) continue;
  visited.add(current.node);

  if (current.node === 'vulnerable-lib') return current.path;

  for (const dependency of dependenciesOf(current.node)) {
    queue.push({node: dependency, path: [...current.path, dependency]});
  }
}
```

BFS được chọn vì requirement là **ít dependency hops nhất**; HashSet chỉ hỗ trợ tránh revisit, không quyết định traversal order.

## When to Use

- Dùng Tree mental model khi dữ liệu thực sự có hierarchy rõ ràng như AST hoặc directory structure.
- Dùng Graph khi relationship có thể many-to-many, cross-link hoặc cycle.
- Dùng BFS khi cần khám phá theo layer hoặc shortest path theo số hop trong unweighted graph.
- Dùng DFS khi muốn đi sâu từng branch, xử lý recursive structure hoặc làm nền cho các algorithm sâu hơn.
- Với BFS/DFS trên graph thực tế, cân nhắc `visited` ngay khi node có thể được reach từ nhiều path hoặc có cycle.

## Common Mistakes

- **Nghĩ BFS luôn nhanh hơn DFS:** cả hai thường traverse `O(V + E)` khi cần thăm toàn graph; strategy khác nhau ở thứ tự khám phá.
- **Dùng DFS cho shortest path theo hop mà không có lý do khác:** DFS có thể gặp một path dài trước path ngắn.
- **Quên visited:** cycle có thể gây loop vô hạn hoặc duplicate work.
- **Nghĩ BFS → DFS là pipeline mặc định:** hãy chọn một traversal strategy theo requirement.
- **Nhầm Tree với Graph tổng quát:** Tree là một dạng graph bị giới hạn topology chặt hơn.

## Self-test

1. BFS và DFS khác nhau chủ yếu ở điểm nào?
2. Vì sao BFS tìm được shortest path theo số hop trong unweighted graph?
3. DFS “quay lại chỗ rẽ gần nhất” liên quan tới Stack thế nào?
4. `HashSet visited` giải quyết vấn đề gì?

<details>
<summary>Answers</summary>

1. Thứ tự khám phá: BFS đi theo layer bằng Queue; DFS đi sâu branch bằng Stack/recursion.
2. FIFO làm mọi node ở khoảng cách `d` được xử lý trước các node ở khoảng cách `d + 1`, nên lần đầu reach target có số hop tối thiểu.
3. Chỗ rẽ gần nhất được ghi nhớ sau cùng và cần quay lại trước, đúng LIFO.
4. Tránh revisit node, duplicate work và loop vô hạn khi graph có cycle.

</details>
