# System Design

System Design là reasoning process để biến requirements thành architecture có explicit bottlenecks, trade-offs, failure modes và operational boundaries.

## Topic Overview

<KnowledgeMap
  label="System Design topic map"
  levels={[
    [{title: 'Requirements', description: 'Clarify user-visible behavior, scale targets and constraints.'}],
    [{title: 'Workload & Bottleneck', description: 'Find the dominant read, write, latency, throughput or consistency pressure.'}],
    [{title: 'Building Blocks', description: 'Choose storage, cache, queue, compute and communication boundaries.'}],
    [{title: 'Trade-offs', description: 'Make cost, consistency, latency and complexity decisions explicit.'}],
    [{title: 'Failure & Recovery', description: 'Design degraded behavior, retry, isolation and recovery paths.'}],
  ]}
/>
